## Codebase Patterns
- A new CHI translation unit must be added both as a production `Source` and
  to every standalone `GTest` source list that directly links its callers.
- The four HNF baseline GTests build under `build/RISCV/mem/cache/CHI/`; their
  expected suite counts are 15 POCQ, 2 SEQ POCQ, 10 SLCSF, and 9 controller.
- Delayed CHI service messages should copy scalar flit metadata and own all
  variable payloads with value containers such as `vector` and `optional`.
- Couple a delayed operation's kind to its payload with a restricted variant;
  derive the kind from the active alternative instead of storing two fields
  that can disagree.
- Derive terminal response identity from the typed request and keep generic
  status/payload construction private so invalid combinations cannot compile.
- Treat double-buffer queue sizes as one shared logical capacity across all
  registered stages rather than giving each physical deque the full capacity.
- For retryable owned messages, accept an rvalue reference but move from it
  only after admission succeeds so rejection preserves caller ownership.
- Represent an in-flight request as its terminal response reservation, then
  count in-flight, pending, and visible states as one bounded occupancy.
- Express configurable service latency as an absolute completion cycle
  captured at issue, and run completion before issue in each wakeup so newly
  issued work cannot finish in the same cycle.
- Translate owned asynchronous requests into synchronous backend calls only at
  their modeled completion boundary, and map backend retry decisions to typed
  terminal Replay responses rather than Done payload flags.
- Derive replay deadlines from the absolute gem5 `Tick` at the completion
  boundary; service-local cycle numbers are not valid retry timestamps.
- Keep a storage/reset epoch independent from read-only lookup-access
  accounting so replacement touches cannot invalidate coherence snapshots.
