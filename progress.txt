## Codebase Patterns
- A new CHI translation unit must be added both as a production `Source` and
  to every standalone `GTest` source list that directly links its callers.
- The four HNF baseline GTests build under `build/RISCV/mem/cache/CHI/`; their
  expected suite counts are 15 POCQ, 2 SEQ POCQ, 10 SLCSF, and 9 controller.
- Delayed CHI service messages should copy scalar flit metadata and own all
  variable payloads with value containers such as `vector` and `optional`.
- Couple a delayed operation's kind to its payload with a restricted variant;
  derive the kind from the active alternative instead of storing two fields
  that can disagree.
- Derive terminal response identity from the typed request and keep generic
  status/payload construction private so invalid combinations cannot compile.
- Treat double-buffer queue sizes as one shared logical capacity across all
  registered stages rather than giving each physical deque the full capacity.
- For retryable owned messages, accept an rvalue reference but move from it
  only after admission succeeds so rejection preserves caller ownership.
- Represent an in-flight request as its terminal response reservation, then
  count in-flight, pending, and visible states as one bounded occupancy.
- Express configurable service latency as an absolute completion cycle
  captured at issue, and run completion before issue in each wakeup so newly
  issued work cannot finish in the same cycle.
- Translate owned asynchronous requests into synchronous backend calls only at
  their modeled completion boundary, and map backend retry decisions to typed
  terminal Replay responses rather than Done payload flags.
- Derive replay deadlines from the absolute gem5 `Tick` at the completion
  boundary; service-local cycle numbers are not valid retry timestamps.
- Keep a storage/reset epoch independent from read-only lookup-access
  accounting so replacement touches cannot invalidate coherence snapshots.
- When an embedded timed service depends on its owner for clock edges, share
  one advance/order/work-decision helper between production scheduling and
  smoke tests so tests exercise the real reschedule boundary.
- Model an asynchronous controller operation with explicit issue-pending,
  waiting, and response-latched phases; retry only the owned pending request
  and continue the graph from a later service boundary.
- At a registered response boundary, validate the complete operation and
  identity pair, copy owned payload state under a bounded consume budget, and
  defer graph continuation until the next controller service cycle.
- Validate a miss token against the generation of its recorded candidate way,
  not the way a later LRU probe would select; replacement touches may reorder
  candidates without mutating the recorded storage snapshot.
- Model a staged mutation as one in-flight owner of both its request and
  terminal response reservation; acquire transient resources before the sole
  write stage and convert the same reservation to a pending response only at
  the final registered boundary.
- Carry the lookup CommitToken by value in every delayed mutation request and
  validate it in U0 before resource acquisition; stale snapshots become owned
  terminal Replay responses with absolute retry deadlines.
- Preflight unsupported dirty SLC displacement before acquiring transient
  resources, while recognizing semantic no-op writes that need no allocation.
- Revalidate a versioned mutation snapshot immediately before the sole write
  after any resource stall, and use its recorded ways for both preflight and
  allocation so replacement touches cannot redirect the commit.
- Assign each issued service request an earliest completion cycle from its
  operation class; deadline-driven catch-up may traverse multiple structural
  stages on one edge but must stop at a resource stall, while early Replay
  explicitly replaces the deadline with the one-cycle completion rule.
- Keep the sole persistent write stage parked until its configured service
  deadline; pre-deadline decode and resource preparation may advance, but
  terminal catch-up must not make architectural mutation visible early.
- Latch a delayed Replay reason when detected, then construct its absolute
  retry deadline at terminal cleanup so pipeline delay does not consume the
  configured replay penalty.
- Test staged stale-token recovery at both resource boundaries: one case must
  invalidate while stalled before acquisition, and another after acquisition
  but before the sole write, so reservation ownership and cleanup stay proven.
- Pass the owner's absolute Tick into controller service boundaries that gate
  retries; a no-argument test seam must not be used by production scheduling.
- When multiple transaction classes share asynchronous issue and wait nodes,
  discriminate their terminal graph edges and response payloads by operation
  kind so each class emits only its own protocol completion.
- Route side effects produced by periodic controller service through an owned
  deferred queue, include that queue in work detection, and let the owning
  event loop drain it exactly once on a later scheduling boundary.
- For a directory-only transaction that still requires token validation,
  perform a registered lookup first and issue the typed mutation from the
  lookup-completion graph edge; emit protocol completion only after Done.
- Classify delayed service timing by the concrete semantic operation rather
  than its payload-bearing variant, since a data-carrying update may still
  consume update issue width and update latency instead of the fill pipe.
- Convert a held capacity reservation into occupied storage before installing
  a victim, and carry the copied victim snapshot in the terminal response so
  reservation accounting and delayed handoff have one atomic ownership point.
- Give internal controller transactions the same explicit issue/wait phases
  as external entries, retaining one owned request and ID across NoCredit;
  route their sentinel response namespace before main-entry bounds checks.
- Before overwriting persistent storage, reserve bounded transient capacity,
  copy the exact versioned victim into it, and require that owned snapshot at
  the write boundary so capacity failure and conflicts remain mutation-free.
- Give an internal downstream transaction both its stable storage-owner ID and
  a separate wire transaction ID; retain its owned payload across TX
  backpressure and match terminal completion through the explicit ID map
  without consuming or delaying the originating POCQ token.
- Keep an acknowledged resource owner work-visible after downstream completion
  until its typed release request returns terminal Done; retain one request ID
  and owned message across NoCredit retries.
- Treat a durable terminal response as a producer-bound acknowledgement lease:
  pending/visible response ownership must remain allocated until the consumer
  ACKs the exact current response, and the producing service must be noncopyable.
- Whenever a timing wrapper forwards `sendTimingSnoopResp()` and can propagate
  backpressure, its corresponding RequestPort must forward
  `recvRetrySnoopResp()` to the original upstream sender.
- Give cross-component machine traces explicit provenance instead of inferring
  an internal transaction from opcode or ID ranges; validate configuration,
  payload identity, ordering, and workload oracles together.
- Acquire multi-class transient resources atomically before exposing any
  ownership, then retain one owner token in the in-flight entry and release it
  through the common terminal finalizer for Done, Replay, Error, and cancel.
- Validate independent concurrency limits in isolated subcases, then require
  every parallel regression to drain queues, locks, reservations, victims,
  and SEQ state so eventual progress cannot hide resource leakage.
- When extracting an embedded service into a SimObject, let the ClockedObject
  own the ordinary noncopyable service by value and let its parent and clients
  retain only configured or non-owning pointers across the ownership boundary.
- Preserve legacy parent configuration paths as Parent-proxy defaults on the
  canonical child; verify final precedence and clock ownership in generated
  config.ini rather than relying on pre-resolution Python assignments.
- Let an ordinary service report newly available work without owning events;
  its ClockedObject wrapper should schedule the sole service event and notify
  consumers only about registered transitions on a strictly future edge.
- Put cold-only destructive reset in `initState()` and start modeled latency
  from `startup()` so checkpoint restore never accidentally clears restored
  state; publish completion through registered state and future notification.
